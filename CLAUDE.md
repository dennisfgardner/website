# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

A static personal website for Dennis F. Gardner Jr., Ph.D. — a physicist/systems engineer/AI-ML researcher who is job-hunting. The published site is plain HTML and CSS with two per-post CDN libraries (KaTeX, Prism); there is no client-side framework and no build step in hosting. Cloudflare serves this repo's files directly on every push, so **the generated HTML and images are committed** and `cv_to_html.py` runs locally.

## Structure

- `index.html` — homepage with intro and links to other pages
- `about.html` — bio, expertise badges, work experience timeline, education, awards
- `publications.html` — 19 peer-reviewed papers, 5 patents, 3 trade articles
- `contact.html` — real contact info (email, phone, Vienna VA, Google Scholar)
- `blog.html` — blog index: one card per post, linking to the post pages (generated)
- `blog-<slug>.html` — one page per blog post, body converted from Markdown (generated; currently `blog-nitf-io.html` and `blog-2d-ipp-cfar.html`)
- `posts/*.md` — **blog post bodies, authored in Markdown** (the real source; `blog_posts.py` holds only metadata)
- `images/<slug>/` — figures for a given post, referenced from its Markdown by repo-root-relative path
- `thesis.html` — Ph.D. thesis page: title/degree block + embedded PDF viewer + download button (generated; see below)
- `Gardner_thesis.pdf` — the compiled thesis PDF that `thesis.html` embeds and links to
- `styles.css` — **the single source of truth for all site styling** (every page links it)
- `blog_posts.py` — blog post **metadata** (slug, title, date, Markdown source path, excerpt, tags, repo link, `math`/`code` flags)
- `cv_to_html.py` — Python script that parses `CV_ver19_20260706.tex`, `blog_posts.py`, and the Markdown in `posts/`, and regenerates **all HTML pages** (six fixed pages plus one per blog post)
- `requirements.txt` — the two build-time Python dependencies (`markdown`, `pymdown-extensions`)

All pages link one external stylesheet, `styles.css` — there is no inline CSS. The color scheme is `#0ea5e9` (teal accent), `#111827` (near-black text), `#ffffff` (page background), `#6b7280`/`#374151` (grays), `#f0f9ff` (accent tint on badges/cards). The nav and footer HTML come from the shared `nav()` helper and `FOOTER` constant in `cv_to_html.py`; every page is generated, so there is no duplicated layout markup. The stylesheet `<link>` is generated by `stylesheet_href()`, which appends `?v=<md5 of styles.css>` so browsers fetch fresh CSS after every regeneration instead of serving a stale cached copy.

Nav order: Home → About → Publications → Blog → Thesis → Contact. The current page's nav link gets `class="active"` (styled in `styles.css`); post pages mark **Blog** active.

`page()` takes optional `head_extra` and `scripts` arguments, injected before `</head>` and `</body>`. This is how KaTeX and Prism are loaded **only** on the post pages that declare `math`/`code` — see `post_assets()`.

## Updating content from the CV

**All HTML pages are generated — do not hand-edit `index.html`, `about.html`, `contact.html`, `publications.html`, `blog.html`, `thesis.html`, or any `blog-<slug>.html`.** Regenerating overwrites them. Edit the source instead, then run `venv/bin/python cv_to_html.py`:

- **CV-derived content** (index/about/contact/publications) → edit `CV_ver19_20260706.tex`
- **Blog post bodies** → edit the Markdown in `posts/`
- **Blog post metadata** → edit `blog_posts.py` (the `POSTS` list)
- **Thesis title/degree/abstract** → edit the `THESIS_INFO` dict at the top of `cv_to_html.py` (not tex-derived, since the CV has no thesis section)
- **Styling for any page** → edit `styles.css`

Beyond the stdlib the script needs only `markdown` and `pymdown-extensions` (see Development below). It parses LaTeX sections delimited by `\section{...}` via `parse_work_experience`, `parse_education`, `parse_enumerate` (publications/patents), `parse_awards`, and `parse_expertise`. `render_blog()` builds the blog index and `render_post()` each post page, both from `blog_posts.POSTS`; `render_thesis()` builds the thesis page from `THESIS_INFO`/`THESIS_PDF`.

**If the CV is renamed or a new version dropped in, update `CV_PATH` at the top of `cv_to_html.py`** — `main()` reads the CV before rendering anything, so a stale `CV_PATH` exits 1 and regenerates nothing, blog included. This has already bitten once.

Each peer-reviewed publication `\item` ends with `\href{https://doi.org/<DOI>}{link}`, which renders as a small "link" badge to the paper's abstract page (styled via `.pub-text a` in `styles.css`). New publication entries should follow the same convention — find the DOI and append it the same way.

## Changing the look of the site

All styling lives in `styles.css`; the `render_*` functions emit only HTML and class names, never CSS. Add a class there, then reference it from the relevant `render_*` function.

## Updating the homepage headshot

`index.html` references `headshot_web.jpg`, which `generate_headshot()` regenerates from `headshot.jpeg` on every run (longest edge `HEADSHOT_MAX_PX` = 600 px, using macOS `sips` if present and ImageMagick `convert` otherwise). Drop in a new `headshot.jpeg` and rerun the generator. If the source photo or both tools are missing, the resize is skipped with a note and page generation still succeeds.

Because it is rewritten on **every** run, the re-encode shows up as a binary diff even when
the source photo has not changed — `git checkout headshot_web.jpg` if you did not mean to
include it in a commit.

## Development

Set up the build dependencies once:

```bash
python3 -m venv venv
venv/bin/pip install -r requirements.txt
```

Then regenerate and preview:

```bash
venv/bin/python cv_to_html.py
python3 -m http.server 8080
```

`venv/` is gitignored. Cloudflare never runs any of this — it serves the committed HTML
directly — so remember to commit the regenerated pages along with the sources.

A `venv/` can exist without the dependencies in it (it is gitignored, so it does not travel
between machines). If `cv_to_html.py` dies with `ModuleNotFoundError: No module named
'markdown'`, the fix is to rerun the `pip install -r requirements.txt` above, not to recreate
the venv.

## Writing a blog post

Post bodies are **Markdown in `posts/<slug>.md`**, converted to HTML at build time (not in
the browser), so pages stay crawlable and styled by `styles.css`.

1. Write `posts/<slug>.md`. **No `<h1>`** — the title comes from `blog_posts.py` and would
   render twice. (markdownlint's MD041 will complain about this; ignore it.)
2. Put figures in `images/<slug>/`, referenced as `images/<slug>/foo.png` — paths are
   relative to the repo root, where the generated HTML lives, not to the `.md`. Downscale
   large ones to ~1200–1600 px wide. **ImageMagick is not installed on the Mac this site is
   authored from**, so on macOS use `sips`; the `convert` form only works on the Linux box:

   ```bash
   sips -s format jpeg -s formatOptions 82 --resampleWidth 1600 big.png \
       --out images/<slug>/big.jpg          # macOS
   convert big.jpg -resize 1200x -quality 82 images/<slug>/big.jpg   # Linux
   ```
3. Add an entry to `POSTS` in `blog_posts.py`, newest first (there is no date sorting). Set
   `"code": True` for fenced code, `"math": True` for equations — these gate the per-page
   CDN tags, so a post that sets neither ships zero JS.
4. `venv/bin/python cv_to_html.py` → writes `blog.html` and `blog-<slug>.html`.

Three conventions worth knowing before editing the pipeline:

- **Math** — `$...$` / `$$...$$`. `pymdownx.arithmatex` (generic mode) converts it to
  `\(...\)`/`\[...\]` at build time and KaTeX renders it. Keep the math pass at build time:
  it is what stops shell variables like `$IPPROOT` in a ```` ```bash ```` block from being
  eaten as math.
- **Code** — fence with a language tag. Prism's autoloader needs an explicit
  `data-autoloader-path` on a CDN or grammars 404 silently; `post_assets()` sets it.
- **Figures** — Markdown has no figure syntax, so write the caption as one bold line under
  the image. `wrap_figures()` promotes an image-only paragraph to `<figure>` and absorbs
  that bold line as the `<figcaption>`.

### Re-syncing the CFAR post

`posts/2d-ipp-cfar.md` is a **copy** of the README of `github.com/dennisfgardner/2D_ipp_CFAR`,
edited for publication (H1 dropped, image paths rewritten, stale `src/` paths and typos
fixed, captions and a closing link added). The site builds standalone and never reads that
repo. To pull upstream changes in, re-copy and re-apply those edits:

```bash
cp /home/dennis/repos/2D_ipp_CFAR/readme.md posts/2d-ipp-cfar.md   # lowercase readme.md
cp /home/dennis/repos/2D_ipp_CFAR/figs/*.png \
   /home/dennis/repos/2D_ipp_CFAR/imgs/cpp_output.png images/2d-ipp-cfar/
convert /home/dennis/repos/2D_ipp_CFAR/imgs/example_image.jpg \
    -resize 1200x -quality 82 images/2d-ipp-cfar/example_image.jpg
```
